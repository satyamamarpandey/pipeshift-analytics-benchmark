# PipeShift: silent errors in LLM-generated analytics code under data-pipeline change

Research artifact for the paper *"When Data Pipelines Change: A Controlled Evaluation of Silent Errors in
LLM-Generated Analytics Code"* by Satyam Adharchandra Pandey (Independent Researcher). The manuscript was
prepared for the TrustAI-BD 2026 workshop at IEEE Big Data 2026.

**Release `v1.1.0`.** The experiment results, generated programs, prompts and code under test are identical to those of the earlier release `v1.0.0` (see *Release history*).

## What the study measures

PipeShift asks whether analytics code written by large language models notices when its input data change
underneath it, or whether it returns plausible but wrong numbers (a *silent error*).

- **Task.** One analytical task: five summary metrics over a 5,000-record snapshot of NYC TLC yellow-taxi
  trips.
- **Snapshots.** 24 stratified snapshots: 12 months of 2025 x 2 replicates. 2024-12 is a prior-period
  reference.
- **Scenarios.** 32 main scenarios: 31 injected faults plus a clean control. Each has a label fixed before
  any generation: recover or abstain.
- **Held-out scenarios.** 3 held-out scenarios, defined after the main results and reported as exploratory.
- **Models.** claude-haiku-5-5, claude-sonnet-5-5 and claude-opus-5-5 (through the Claude Code CLI), and the
  open-weight Qwen2.5-Coder-7B-Instruct (Q4_K_M, llama.cpp).
- **Prompts.** Three conditions: A unassisted, B contract-guided and C provenance-guided.
- **Generations.** 10 per model and condition, giving 120 generations (119 with extractable code; one Qwen generation, `A_unassisted__06`, produced no extractable code and is scored `invalid_output`). These are the statistical
  unit.
- **Executions.** Every generation is executed on every episode: 46,080 main executions (120 x 384) and 4,320
  held-out executions (120 x 36). The generation without extractable code is scored `invalid_output` on all of them.
- **Baselines.** Eight deterministic baselines (B0-B7), ablations and a compromised trust-anchor (manifest) experiment. B2, B6 and B7 receive inputs (previous-month statistics, an independent registry) that no prompt gives the LLM workflows.

**What the benchmark can and cannot show.** Prompts B and C state most of the rules that define the labels, so for those scenarios the results measure whether a model *implements a supplied contract*. Only the three held-out scenarios (H01-H03, exploratory and defined after the main results) probe faults that no prompt mentions. Nothing here shows that a model can discover unseen faults on its own.

## Setup

Requirements:

- Python 3.13. Tested on 3.13.16 under Windows 11.
- About 2 GB of disk space.
- Network access to the TLC distribution.

```bash
python -m venv .venv
.venv/Scripts/python -m pip install -r requirements-lock.txt     # Windows
# .venv/bin/python -m pip install -r requirements-lock.txt       # Linux / macOS
```

- `requirements-lock.txt` pins the exact tested versions.
- `requirements.txt` lists the direct dependencies. Other versions have not been tested.

## Data

The data are the official NYC TLC Yellow Taxi monthly Parquet files: 2024-12 and 2025-01 to 2025-12. The
source page is <https://www.nyc.gov/site/tlc/about/tlc-trip-record-data.page> and the data dictionary is
<https://www.nyc.gov/assets/tlc/downloads/pdf/data_dictionary_trip_records_yellow.pdf>.

The study uses 13 files (about 891 MB, 52,390,973 rows; the 12 study months hold 48,722,602 rows). The raw files are **not redistributed**. `pipeshift/acquire.py` downloads them into `data/raw/` and fails
closed if a file's SHA-256 differs from `data/source_manifest.json`; an upstream revision would make it a
different experiment. TLC states that trip records are submitted by technology providers and that their
accuracy and completeness are not guaranteed.

## Reproduce

```bash
python reproduce.py                 # download, rebuild snapshots/episodes/oracle, rerun baselines, re-execute LLM code, compare
python reproduce.py --skip-download # reuse data/raw
python reproduce.py --quick         # also skip full-month timing
python -m pytest -q tests           # test suite
python pipeshift/verify_numbers.py  # recompute headline numbers independently and compare with paper/generated_macros.tex
```

`reproduce.py` prints `REPRODUCTION PASSED` when the regenerated episode outcomes match the archived ones.
Timing measurements depend on the machine and are not compared.

Reference results of a clean-environment run of this release (2026-11-15; new virtual environment from `requirements-lock.txt`, Windows 11, Python 3.13):

- 46,080/46,080 main and 4,320/4,320 held-out LLM episode outcomes identical to the archive;
- baselines identical;
- all 13 source hashes verified;
- 93 tests passed (0 skipped) after the data download; 86 before it (data-dependent tests skip);
- `verify_numbers.py`: 66 numbers, 0 mismatches.

The same steps were run earlier on the author's private archive (2026-10-23, 162 tests including the legacy v1 prototype tests, which are not part of this release). These are same-machine checks run through the author's AI-assisted workflow, not independent replication.

## Expected results (validation targets)

After `python reproduce.py`, `python pipeshift/verify_numbers.py` should report `66 numbers checked independently; 0 mismatches`. Key values (Claude models pooled; 30 generations per condition; 95% cluster-bootstrap intervals over programs; machine-dependent timing is not compared):

| Quantity | A unassisted | B contract-guided | C provenance-guided |
|---|---|---|---|
| Silent-error rate (all 32 scenarios) | 22.2% | 13.2% | 5.3% |
| Silent-error rate (15 metric-changing scenarios) | 45.6% | 28.1% | 11.3% |
| False rejection (recover-desired scenarios) | 29.2% | 10.1% | 17.0% |
| Held-out H01-H03 silent-error rate (exploratory) | 93.3% | 100.0% | 96.7% |

Deterministic baselines (768 main episodes each): B5 (contract + manifest) 5.5% silent errors, 0% false rejection; B7 (B5 with an independent registry) 2.3%; only B7 detects the jointly forged data file and manifest (scenario P04). Qwen2.5-Coder-7B: 5 of 30 generations functional (A 4, B 1, C 0). Totals: 46,080 main and 4,320 held-out episodes.
The tables are in `results_v2/tables/` and the paper's numbers in `paper/generated_macros.tex`.

## Reproducing tables and figures

`reproduce.py` regenerates `results_v2/tables/`, `paper/generated_macros.tex`, `paper/generated_tables/` and `figures_v2/`. To rebuild only the analysis from the archived episode records: `cd pipeshift && python analysis.py && python figures.py`. Figure 3 (`fig_fault_heatmap`) is drawn with vector cells in this release (`v1.0.0` rasterised it at 100 ppi; the data are identical).

### Re-execution versus re-sampling

`reproduce.py` **does not re-sample the models**. It re-executes the archived generated programs in
`results_v2/llm/generations/` in the sandbox and re-scores them against a freshly rebuilt oracle. This
reproduces every reported outcome from the archived generations, but it is not an independent replication
of model sampling.

New samples would form a new experiment:

- The Claude Code CLI does not expose sampling temperature; the provider default applied.
- Model versions change over time.

To draw a new sample:

- Claude: `python pipeshift/llm_generate.py --backend claude-cli --model <id> --n 10`. Requires an
  authenticated Claude Code CLI; cost is capped by `--budget-usd`.
- Open-weight model: `--backend llamacpp` against a local llama.cpp server. The weights are not
  redistributed; `docs/environment/environment.md` names the source and SHA-256.

## Redacted values in the released records

Some generated programs raise exceptions whose message quotes a value from the input records (for example a timestamp such as `time data "<value>" doesn't match format ...`, or a long run of concatenated fare values). Such quoted source values are replaced by `<value>` in the `reason` column of the released episode records (918 cells in the packaged copies of the records; `pipeshift/redact.py`, applied once by `pipeshift/redact_records.py`, and now also at the source in `llm_evaluate.sanitize` and `run_baselines.py`). No other cell changed; outcomes, metrics, tables and the paper's numbers are unaffected, and `reproduce.py` compares outcomes only. Regenerated `reason` text can differ slightly from the archived text where a redacted value shortened the message before the 200-character cut-off. The author's private archive keeps the original, unredacted records.

## Corrected sandbox stderr handling

The first main-suite evaluation had a harness defect. The sandbox interpreter's stderr was a pipe that was
read only after the process ended. One Qwen generation writes about 290 bytes of warnings per episode, so
after 14 episodes the 4 KB Windows pipe buffer filled, the interpreter blocked, and the watchdog scored the
episode as a timeout (`invalid_output`).

- **Fix.** The current harness writes stderr to a file.
- **Effect.** The main suite was re-executed without re-sampling. Only 24 Qwen episodes changed, from
  `invalid_output` to `silent_error`.
- **Verification.** The corrected outcomes are identical to an independent clean-environment rebuild in
  all 46,080 episodes.
- **Regression test.** `test_sandbox_verbose_stderr_does_not_deadlock` in `tests/test_v2_harness.py` fails
  on the old harness and passes on the current one.

The records produced by the defective harness are kept, clearly labelled, in
`results_v2/llm/superseded_pipe_deadlock/`. They are **not** the reported results. See `docs/DEVIATIONS.md`,
item 5.

## Sandbox caveat

Generated code runs:

- in a separate interpreter with a clean environment and an empty working directory;
- under wall-clock timeouts;
- with a Python audit hook that blocks sockets, subprocesses and file access outside the episode inputs.

This is a best-effort research sandbox, **not a security boundary**. Run untrusted generated code only on a
disposable machine or container.

## Scientific limitations

These limitations are stated in the paper and repeated here.

- **Data.** One data source: NYC TLC yellow-taxi records, 2025.
- **Task.** One deliberately simple task (five summary metrics).
- **Snapshot size.** 5,000-record snapshots.
- **Models.** Four models, three of them from the same model family.
- **Prompt wording.** One wording per prompt condition.
- **Prompt guidance.** Prompts B and C state most of the rules that define the labels. For those scenarios
  they measure whether a model *implements* a given contract, not whether it anticipates faults.
- **Held-out scenarios.** Only three, chosen after the main results; exploratory.
- **Qwen.** Only 5 of the 30 Qwen generations were functional. Its low silent-error rate under guidance
  reflects universal rejection, not correct validation.
- **Compromised manifest.** The experiment shows that checks anchored on a manifest fail when the manifest
  itself is altered; SHA-256 verifies agreement, not authenticity.
- **Record keys.** The benchmark assigns a synthetic `record_id`, so replay and conflict results do not
  transfer directly to keyless TLC data.
- **Archive status.** The reported checks re-execute archived programs on rebuilt official data. They were run by the author's AI-assisted workflow on one machine; they are not independent human replication and not fresh model sampling.
- **Independence.** The research software was developed with the help of Claude Code (see below), which
  belongs to the same model family as three of the evaluated models.
